# 테스트 케이스

문항마다 **정확히 10개**의 입력과 기대 출력을 제공합니다. 공식 시험 데이터가 아니라 이 저장소의 재구성 규칙을 검증하기 위해 만든 데이터입니다. 기대값은 입력의 구조를 근거로 고정했으며, 생성기가 정답 풀이를 실행해 출력값을 만들지는 않습니다.

[cases.py](cases.py)는 표준 라이브러리만 사용합니다. 이 파일이 있는 디렉터리에서 다음 명령을 실행하면 큰 입력까지 포함한 JSON 파일을 실제로 생성합니다.

```bash
python3 cases.py --output generated-tests
```

각 문항에 `01`부터 `10`까지 입력·출력 쌍이 생깁니다. 두 문항을 합쳐 입력 20개와 출력 20개, 총 40개 파일입니다.

```text
generated-tests/
  01-square-regions/
    01.in.json
    01.out.json
    ...
    10.in.json
    10.out.json
  02-ticket-exchange/
    01.in.json
    01.out.json
    ...
    10.in.json
    10.out.json
```

입력 JSON은 함수 인자의 목록을 `args`에 담습니다. 출력 JSON은 함수가 반환해야 하는 정수 또는 문자열 하나입니다. 예를 들어 첫 문항의 1번 입력과 출력은 다음과 같습니다.

```json
{"args":[[[1,2],[3,4]]]}
```

```json
0
```

두 번째 문항은 `{"args":[preferences,requests]}` 형식이고, 출력에는 `"ocean"`처럼 JSON 문자열을 씁니다. 대형 격자의 파일 크기를 줄이기 위해 들여쓰기를 넣지 않습니다. 같은 출력 디렉터리에서 다시 실행하면 해당 번호의 파일을 덮어씁니다.

Python에서 직접 사용할 때는 `make_cases("01-square-regions")` 또는 `make_cases("02-ticket-exchange")`를 호출하세요. 각각 다음 구조의 사전 10개가 담긴 목록을 반환합니다.

```python
{"id": "01", "name": "한국어 검증 항목", "args": [...], "expected": ...}
```

큰 입력도 축약 설명이나 파일 경로가 아닌 실제 배열로 반환됩니다. 따라서 전체 목록을 보관할 만큼의 메모리가 필요합니다.

## 문항 1: 완성된 정사각형 타일 묶음

| 번호 | 크기 | 검증 목표 | 기대 출력 |
| --- | --- | --- | --- |
| 01 | `2 × 2` | 최소 격자에서 번호가 서로 다른 한 칸짜리 묶음은 모두 제외 | `0` |
| 02 | `4 × 4` | 번호 `0~3`의 독립된 `2 × 2` 묶음 네 개를 각각 계산 | `4` |
| 03 | `3 × 3` | 전부 번호 `7`인 하나의 완성품 내부에서 부분 정사각형을 중복 계산하지 않음 | `1` |
| 04 | `3 × 3` | `2 × 2` 묶음에 대각선으로 붙은 같은 번호의 추가 타일까지 포함 | `0` |
| 05 | `3 × 3` | 테두리의 번호가 같아도 가운데 타일이 다른 번호이면 해당 묶음은 미완성 | `0` |
| 06 | `2 × 3` | 빈틈없는 직사각형이어도 가로와 세로 길이가 다르면 제외 | `0` |
| 07 | `2 × 2` | 번호 `0`도 유효한 타일 번호이며 최소 크기의 완성품으로 계산 | `1` |
| 08 | `1,000 × 1,000` | 최대 크기의 단일 연결 묶음: 재귀 깊이, 전체 순회 비용과 메모리 확인 | `1` |
| 09 | `1,000 × 999` | 큰 묶음을 끝까지 확인하되 정사각형이 아닌 경우 제외 | `0` |
| 10 | `1,000 × 1,000` | 독립된 `2 × 2` 완성품 25만 개: 많은 묶음의 처리 비용과 큰 반환값 확인 | `250000` |

10번은 위치 `(r, c)`의 번호를 `2 * ((r // 2) % 2) + ((c // 2) % 2)`로 정합니다. 인접한 `2 × 2` 블록은 대각선 방향까지 모두 번호가 다르므로 서로 연결되지 않습니다. `500 × 500`개의 블록이 각각 완성품이 됩니다. 두 번호만 번갈아 배치하면 같은 번호의 블록들이 대각선으로 이어지므로 이 목적에 맞지 않습니다.

## 문항 2: 가장 마음에 드는 체험 부스

`P`는 선호 목록의 부스 수, `R`은 제안 수입니다. 마감 시각 포함, 선호도 하락 허용, 목록 밖 이름이 포함된 제안 전체 제외, 이름의 대소문자 구분 규칙을 적용합니다.

| 번호 | 크기 | 검증 목표 | 기대 출력 |
| --- | --- | --- | --- |
| 01 | `P=4`, `R=3` | 기억 예제를 `art → robot → space → ocean`으로 바꾼 기본 연쇄 | `"ocean"` |
| 02 | `P=3`, `R=2` | `10:00`에 얻은 이용권으로 `10:00`에 마감되는 제안을 즉시 이용 | `"space"` |
| 03 | `P=4`, `R=4` | `10:01` 도착으로 `10:00` 마감을 놓친 경우와 미등록 부스 `ghost`를 경유하는 가짜 경로 제외 | `"robot"` |
| 04 | `P=7`, `R=6` | 입력은 교환 순서의 역순이어도 `12:00`에 여섯 번 연속 교환 가능 | `"ocean"` |
| 05 | `P=4`, `R=3` | `art → space → robot → ocean`에서 중간 선호도 하락 허용 | `"ocean"` |
| 06 | `P=4`, `R=4` | `00:00`에 출발해 대기하며 이동, 순환 제안 처리, `23:59` 마감 형식 확인 | `"ocean"` |
| 07 | `P=4`, `R=4` | 늦은 직행으로 먼저 발견한 부스의 도착 시각을 빠른 우회 경로로 갱신 | `"ocean"` |
| 08 | `P=2`, `R=1` | 부스 수와 제안 수의 최소 경계, 교환 방향 및 대소문자 구분, 교환하지 않는 선택 | `"art"` |
| 09 | `P=3,000`, `R=3,000` | 역순으로 주어진 길이 2,999의 연쇄와 시작점으로 돌아오는 순환 | `"belj"` |
| 10 | `P=3,000`, `R=3,000` | 많은 분기와 같은 두 부스 사이의 제안 여러 개를 처리하며 가장 빠른 도착을 유지 | `"belj"` |

9번과 10번의 부스 이름은 모두 서로 다른 소문자 네 글자이며, `baaa`부터 `belj`까지 생성합니다. 입력에 숫자가 들어간 이름을 사용하지 않습니다. 모든 제안은 `00:00~23:59` 범위에서 시작이 마감보다 빠릅니다.

9번은 `baaa`에서 시작하는 모든 연쇄 제안이 같은 시간 구간에 유효하므로 끝 부스 `belj`에 도착할 수 있습니다. 제안 순서대로 한 번만 검사하는 풀이와 연쇄를 재귀로만 처리하는 풀이를 점검할 수 있습니다.

10번은 시작점에서 두 번째 부스로 가는 제안을 늦은 것, 빠른 것 순서로 놓습니다. 빠른 제안으로 `00:00`에 두 번째 부스를 얻으면 `09:00`에 최상위 부스 `belj`로 이동할 수 있습니다. 나머지 2,997개 제안은 시작점에서 다른 부스로 뻗는 분기입니다.

## 경계와 실행 시간 확인

- 정확성은 각 테스트의 실제 반환값을 기대 출력과 비교해 확인합니다.
- 문항 1의 08~10번은 최대 격자에서 연결 묶음 하나와 묶음 25만 개를 각각 처리하게 합니다.
- 문항 2의 09~10번은 부스 수와 제안 수를 모두 상한까지 사용하며 긴 연쇄, 순환, 분기, 평행 제안을 포함합니다.
- 실행 시간과 메모리는 언어, 인터프리터, 컴파일 옵션 및 실행 환경에 따라 달라집니다. 제출 실행기의 시간 제한은 측정 환경에 맞게 조정해야 합니다.
- 이 10개 테스트만으로 모든 비효율적인 알고리즘이나 잘못된 풀이를 확정적으로 걸러낼 수는 없습니다. 특히 초 단위 제한이 느슨하면 비효율적인 풀이도 통과할 수 있으므로 복잡도 검토와 함께 사용하세요.
