# 가장 마음에 드는 체험 부스

> 전달받은 기억을 바탕으로 만든 2026-Q3 코딩 연습 문제입니다. 공식 출제문이 아니며, 소재와 문장은 새로 작성했습니다. 아래에 명시한 보완 규칙을 기준으로 풀이와 테스트를 제공합니다.

## 문제

체험 박람회에는 여러 부스가 있습니다. 당신은 자정인 `00:00`에 이용권 한 장을 가지고 있으며, 처음 가진 이용권의 부스 이름은 `preferences[0]`입니다.

`preferences`에는 부스 이름이 덜 가고 싶은 곳부터 더 가고 싶은 곳 순서대로 적혀 있습니다. 배열의 뒤쪽에 있는 부스일수록 선호도가 높습니다.

교환 게시판에는 다음 형식의 제안들이 올라와 있습니다.

```text
[교환 시작 시각, 교환 마감 시각, 내가 받을 부스, 내가 건넬 부스]
```

제안의 네 번째 부스 이용권을 가지고 있다면, 유효 시간 안에 그 이용권을 건네고 세 번째 부스 이용권을 받을 수 있습니다. 예를 들어 `["09:00", "12:00", "robot", "art"]`는 `art → robot` 교환입니다.

다음 규칙에 따라 교환할 수 있습니다.

- 시작 시각과 마감 시각을 모두 포함합니다. `10:00`에 마감되는 제안은 정확히 `10:00`에도 이용할 수 있습니다.
- 교환 자체에는 시간이 들지 않습니다. 같은 시각에 여러 번 이어서 교환해도 됩니다.
- 이용권을 가진 채 원하는 시각까지 기다릴 수 있습니다. 시간은 거꾸로 흐르지 않습니다.
- 매 순간 이용권은 한 장만 보유합니다. 교환하면 기존 이용권은 사라집니다.
- 더 좋은 결과를 위해 중간에 선호도가 낮은 부스로 바꾸어도 됩니다.
- 교환을 전혀 하지 않거나, 원하는 시점에 중단해도 됩니다.
- 두 부스 중 하나라도 `preferences`에 없다면 해당 제안 전체를 제외합니다.

하루 동안 가능한 교환을 선택했을 때, 최종적으로 가질 수 있는 이용권 중 선호도가 가장 높은 부스의 이름을 반환하세요.

## 함수

Python:

```python
def solution(preferences, requests):
    # 부스 이름 문자열을 반환합니다.
    pass
```

C++17:

```cpp
string solution(vector<string> preferences, vector<vector<string>> requests);
```

## 매개변수와 제한

| 매개변수 | 의미 | 범위 |
| --- | --- | --- |
| `preferences` | 선호도가 낮은 순서로 나열한 서로 다른 부스 이름 | 2~3,000개 |
| `requests` | 순서가 정해지지 않은 교환 제안 | 1~3,000개 |
| 부스 이름 | 대소문자를 구분하는 영문 알파벳 문자열 | 길이 1~10 |
| 시각 | 같은 날의 `HH:MM` 형식 | `00:00`~`23:59` |

각 제안은 문자열 네 개로 구성되며 시작 시각은 마감 시각보다 빠릅니다. 날짜를 넘기는 제안은 없습니다. 입력 배열에서 제안이 나열된 순서는 교환 순서와 무관합니다.

## 예제 1

```python
preferences = ["art", "robot", "space", "ocean"]
requests = [
    ["09:00", "18:00", "space", "robot"],
    ["10:00", "11:00", "robot", "art"],
    ["10:30", "10:31", "ocean", "space"],
]
```

```text
반환값: "ocean"
```

`10:30`에 `art → robot → space → ocean`으로 연달아 바꿀 수 있습니다. 세 제안이 이 시각에 모두 유효합니다.

## 예제 2

```python
preferences = ["art", "robot", "space"]
requests = [
    ["10:00", "11:00", "robot", "art"],
    ["09:00", "10:00", "space", "robot"],
]
```

```text
반환값: "space"
```

`10:00`에 `robot`을 얻은 직후 같은 시각에 `space`로 바꿀 수 있습니다. 마감 시각도 포함하기 때문입니다.

## 예제 3

```python
preferences = ["art", "robot", "space"]
requests = [
    ["10:01", "11:00", "robot", "art"],
    ["09:00", "10:00", "space", "robot"],
]
```

```text
반환값: "robot"
```

`robot`을 얻을 수 있는 가장 이른 시각은 `10:01`입니다. 그때는 `space`를 받을 제안이 이미 끝났습니다.

예제 1은 기억으로 전달된 예제의 부스 이름을 바꾸어 구성했습니다. 예제 2와 3은 경계 시각을 설명하기 위해 새로 만들었습니다.

## 복원 과정에서 정한 규칙

처음 주어진 참석권, 종료 시각 포함 여부, 선호도가 낮아지는 교환, 목록 밖 이름 처리, 이름의 중복 여부는 공식 원문으로 확인하지 못했습니다. 이 연습판은 각각 **첫 번째 부스에서 시작, 종료 포함, 선호도 하락 허용, 목록 밖 이름이 있는 요청 제외, 이름 중복 없음**으로 고정합니다.

전달된 제안 설명의 상대방 관점 표현은 명시적 교환 규칙 및 예제와 방향이 충돌했습니다. 여기서는 예제에 맞춰 **네 번째 항목에서 세 번째 항목으로 교환**한다고 정의했습니다. 실제 원문의 규칙이 다르면 테스트와 풀이도 그에 맞게 바꾸어야 합니다.
